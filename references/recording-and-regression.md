# 录制与回归规则

## 场景与身份

建立简短的场景记录：设备 serial/API/分辨率/刷新率、模拟器或真机、包名/Activity、APK 版本及更新时间、构建类型、源码状态、数据和缓存条件、连接与授权状态。不要清空数据来简化脚本；首次安装、保留数据冷启动、热启动和后台恢复分开记录。

同一设备上的自动操作与录制串行协调，不让多个执行者同时切页。坐标来自当前 UI 层级或截图，每次进入目标页后重新确认。程序性滚动、触摸注入和手动操作是不同输入方式，对照时保持一致。

自动化应有页面、进程和内容断言：列表前中后内容变化；拖动前后对象位置变化；恢复后目标页面存在。预期冷启动会更换 PID，不要套用列表 PID 不变断言。UIAutomator 使用唯一输出文件并验证本次 dump 成功，避免误读旧 XML；页面过渡允许有界等待，超时即记录无效原因。焦点接口随系统变化，应先验证可用输出。

没有输入注入权限时，按已有授权使用合适模拟器或用户手动操作；不宣称读日志权限等于触摸权限。手动模式先确认页面就绪，录制启动后给出分段操作和结束信号。

## 采集质量

使用官方 workflow 支持的数据源和工具。先短录制验证目标事件，再选择覆盖完整操作和收尾静置的时长、缓冲或文件输出方式。动画列表的数据量可能远大于静态页面，不沿用固定小缓冲。

记录 recorder 成功、trace 文件、实际时间范围、目标 PID/UPID/窗口、触摸和有效帧。检查丢失、覆盖、未闭合事件和配置错误；info 级覆盖计数也要检查，不能仅查询 error。覆盖了目标阶段的录制不能用于该阶段结论。按数据量或缩短场景修正配置，而非无限增大资源。

无操作、错页、进程异常变化或缓冲覆盖的样本保留失败原因，不混进基准。录制成功退出不等于场景成功。

## 分析口径

- 先核对 SQL schema，使用官方标准库计算 CPU 等指标。避免猜字段、重复解析巨大 trace 或重复下载已验证工具。
- 进程名可能缺失或暂留 zygote 名称：通过运行时 PID、UPID、窗口和启动事件交叉确认。不能仅凭图层名称中的包名把系统 Splash 或 system_server 的帧计入 App。
- 分开启动、滚动、惯性结束后的静置、切页与恢复。操作日志辅助定位，指标区间优先用 trace 内的实际触摸、窗口和帧；不要把截图完成时间当成 TTID/TTFD。
- 完整帧统计排除未闭合 dur=-1，注明分母。App Deadline Missed、Buffer Stuffing、Prediction Error、系统合成延迟不能合并成应用掉帧率。gfxinfo 与 FrameTimeline 范围及口径不同，不直接混算。
- 墙钟不等于 CPU。父子切片不可相加，后台并发 GC 时长不等于 UI 暂停。渲染线程长等待不等于 GIF 解码或 GPU 执行时长；需相应采样才能继续归因。
- TTID 首帧不代表首页可操作。无可靠 fully-drawn/交互事件就说明缺少 TTFD；固定启动动画时长属于代码规则，不能机械加到 TTID。
- GIF/时钟持续动画有功能需求，静置有帧本身不是缺陷。看是否多余重组、布局、不可见动画或超预算工作。
- 短时 RSS 增长不能证明泄漏。需要重复生命周期循环、稳定观察窗口及必要的堆证据。也不能凭一次无 GC 认定无分配问题。

## 对照回归

复用相同脚本与数据，记录每次实际到达的内容、操作次数及阶段边界。优先固定设备、构建类型、分辨率、素材、缓存冷热、初始位置和连接状态；改变的条件必须注明，不能把热缓存收益算成代码优化。

采样次数按波动决定，不能拿单次极值作稳定百分比改善。系统与 App 同时大幅变慢时，先排查环境和采集干扰，不急于修改业务。debug 模拟器用于定位与功能回归，不能替代同条件发布包/真机基准。

输出可对照的帧数量、分位数、目标慢切片 CPU/墙钟和必要内存指标，同时检查新代码功能。性能变好但内容缺失、动画停播、权限绕过或入口消失仍属回归失败。
